Prompt Eng. --> Context Eng. --> Harness Eng. era

Dr.S · 2026-11-25
AI 에이전트 기술이 발전하면서 개발의 초점이 모델에게 말을 잘 거는 법에서 모델 바깥의 통제 시스템을 잘 짜는 법으로 이동했다는 내용입니다. AI 박사님께서 한눈에 핵심만 파악하실 수 있도록 세 단계의 변화와 실무적 차이를 쉽게 요약해 드립니다. 1. 한 줄 비유로 보는 3단계 진화 프롬프트 엔지니어링 (지시서 작성법): AI에게 일을 시킬 때 어떤 말투와 형식으로 지시해야 가장 좋은 답이 나올지 고민하는 단계입니다. 컨텍스트 엔지니어링 (책상 위 서류 정리법): AI가 한 번에 기억할 수 있는 용량에 한계가 있으므로, 지금 작업에 꼭 필요한 핵심 자료만 골라 요약해서 책상 위에 올려주는 단계입니다. 하네스 엔지니어링 (사무실 업무 시스템 구축법): AI가 여러 단계의 일을 혼자 처리하다가 길을 잃거나 사고를 치지 않도록, 도구 사용 권한, 작업 상태 저장, 오류 자동 복구, 최종 결재(검증) 절차를 모델 바깥에 만들어주는 단계입니다. 2. 왜 하네스 엔지니어링이 핵심이 되었는가? 과거에는 AI가 질문에 한 번 답하고 끝났지만, 최근 1년 사이에는 스스로 자료를 찾고 코드를 수정하며 수십 단계의 작업을 연속으로 수행하는 에이전트가 주류가 되었습니다. AI 모델은 본질적으로 확률에 의존하기 때문에 작업이 길어지면 이전 내용을 잊거나 중간에 오류가 나기 쉽습니다. 결국 아무리 똑똑한 AI라도 그 바깥을 감싸는 단단한 안전장치와 통제 시스템(하네스)이 없으면 실제 비즈니스 현장에 투입할 수 없다는 것이 최신 AI 엔지니어링의 결론입니다. 3. 컨텍스트 vs 하네스 핵심 차이 5가지 자료가 부족할 때: 컨텍스트는 관련 문서를 찾아 프롬프트에 넣어주지만, 하네스는 AI가 직접 검색 도구를 쓰도록 연결하고 결과가 부실하면 재검색하게 만듭니다. 이전 작업을 잊을 때: 컨텍스트는 지나간 대화를 짧게 요약해서 다시 보여주지만, 하네스는 작업 진행 상태를 데이터베이스에 실시간으로 저장해 두고 언제든 그 시점으로 복원합니다. 중간에 오류가 날 때: 컨텍스트는 에러 메시지를 AI에게 보여주며 고쳐보라고 하지만, 하네스는 시스템이 오류를 감지해 자동으로 재시도하고 무한 루프에 빠지지 않게 차단합니다. 목표에서 벗어날 때: 컨텍스트는 원래 목표를 글로 다시 강조하지만, 하네스는 별도의 검증기가 결과물을 채점해 합격 기준에 못 미치면 강제로 반려하고 다시 작성하게 합니다. 여러 단계를 거칠 때: 컨텍스트는 단계별 계획표를 텍스트로 제공하지만, 하네스는 각 단계의 실행 순서와 조건, 외부 도구 호출 권한을 코드 레벨에서 직접 통제합니다. 4. 하네스 시스템의 작동 순서 (A부터 Z까지 한눈에 보기) 실제 현업에서 하네스 엔지니어링이 작동하는 흐름은 다음 5단계의 반복입니다. 상태 불러오기 (A): 데이터베이스에서 현재 작업이 몇 단계까지 진행되었는지 상태를 확인합니다. 컨텍스트 조립 (B): 현재 단계에 꼭 필요한 목표와 직전 요약본만 추려서 AI에게 전달합니다. 도구 실행 및 오류 감시 (C): AI가 외부 검색이나 문서 작성을 실행할 때 허용된 권한인지 검사하고, 네트워크 장애 등이 발생하면 시스템이 자동으로 최대 3회까지 재시도합니다. 중간 저장 (D): 한 단계가 무사히 끝나면 작업 결과를 즉시 저장하여, 다음 단계에서 문제가 생겨도 처음부터 다시 시작하지 않도록 보호합니다. 최종 검증 및 승인 (E): 모든 작업이 끝나면 독립된 검증 장치가 필수 조건 충족 여부를 검사하여, 통과하면 종료하고 미달하면 이전 단계로 되돌려 수정시킵니다.
